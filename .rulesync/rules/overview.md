# Project Overview

`opencode-auto-approval-plugin` is an [opencode](https://opencode.ai/) plugin that auto-approves
tool permission requests based on configurable rules. It is published to npm as an ESM + CJS
package built from `src/index.ts`.

The repository is scaffolded from
[dyoshikawa/ts-template](https://github.com/dyoshikawa/ts-template).

- Manage runtimes and package managers with @mise.toml .
- The toolchain is Vite+ (`vp`): `vp pack`, `vp test`, `vp lint`, `vp fmt` and `vp check`, run
  through the package scripts. `vite.config.ts` holds the build (`pack`), formatter (`fmt`), linter
  (`lint`) and pre-commit (`staged`) settings — there is no `tsdown.config.ts`, `.oxlintrc.json` or
  `.oxfmtrc.json`. Import test APIs from `vite-plus/test` and `defineConfig` from `vite-plus`, not
  from `vite`, `vitest` or `tsdown`.
- AI tool configurations (`AGENTS.md`, `CLAUDE.md`, `.claude/`, `.github/instructions/`, …) are
  generated by [rulesync](https://github.com/dyoshikawa/rulesync) from `.rulesync/`. Never edit the
  generated files directly — edit `.rulesync/**` and run `pnpm generate`.
- When you want to check the entire codebase:
  - `pnpm cicheck:code` checks code style, type safety, and tests.
  - `pnpm cicheck:content` checks spelling and secrets.
  - `pnpm cicheck` checks both. Prefer this for daily checks.
- When doing `git commit`:
  - You must run `pnpm cicheck` before committing to verify quality.
  - You must not use here documents because it causes a sandbox error.
  - You must not use the `--no-verify` option because it skips pre-commit checks and causes serious
    security issues.
  - When creating a PR, you should include a link in the PR description that associates the PR with
    its issue.
- GitHub Actions must always be pinned to full-length commit SHAs. Run `mise run pinact` to pin them
  and `mise run pinact:check` to verify.
- `.devcontainer/` holds the sandboxed dev environment for AI coding agents. `mise.toml` is copied
  into the image at build time, so changing it requires rebuilding the container.
- `mise run trivy` runs the same misconfiguration scan as CI over `.devcontainer/` and
  `.github/workflows/`. Suppress a finding only in `.trivyignore`, and record why it is safe.
